# Feature: Service Providers - Freight Forwarders Edit

As an ADX Manager admin, I want to edit an existing freight forwarder's
details so that its contact information and location stay accurate over
time.

URL: https://adxmanager.dev/v2/service-providers/freight-forwarders/{id}/edit
(opened from a row's kebab menu on the index; on success it redirects to
https://adxmanager.dev/v2/service-providers/freight-forwarders/{id})
Reached via: log in at /system-login -> /home -> /v2/home -> left nav
"Service Providers" > "Freight Forwarders" > a row's ⋮ menu > "Edit".

## Acceptance Criteria

- Given an existing freight forwarder, when a user edits its Contact Name, Telephone Number, Email, and Fax and saves, then a "Freight forwarder updated successfully." confirmation is shown and the detail page reflects the new values.
- Given an existing freight forwarder, when a user edits its Company Name, City, State, and Country and saves, then the detail page shows the new company name and the index list reflects both the new name and the new "{city}, {country}" location.
- Given an existing freight forwarder, when a user clears its Company Name and saves, then a validation error ("The company name field is required.") is shown and its existing name is left unchanged.

## Notes

Tag this feature: `service-providers`, `freight-forwarders`, `edit`

Covered end-to-end in `tests/test_ServiceProviders_FreightForwarders_Edit.spec.ts`.
As with the Suppliers features, the heuristic (non-LLM) Planner fallback in
`agents/planner/plannerAgent.ts` only understands simple email/password
login flows, so this feature's `TestPlan` and the page-object code itself
were authored directly rather than generated by the regex heuristic.

The suite creates its own throwaway fixture (via
`FreightForwardersPage.createFreightForwarder`) rather than editing a real,
pre-existing freight forwarder, so it never mutates shared data. This
section's Edit flow matches Suppliers' (a real `<a href=".../edit">` link in
the row's kebab menu, full page navigation, redirect to the plain detail
URL on success) — confirmed live rather than assumed, since Customs
Brokers' Edit flow (see its own requirements doc) works completely
differently.
