# Feature: Service Providers - Suppliers Create

As an ADX Manager admin, I want to add a new supplier from the Suppliers
index so that it becomes available for sourcing without leaving the page.

URL: https://adxmanager.dev/v2/service-providers/suppliers ("Add Supplier"
button opens the create drawer; the form posts back to the same URL)
Reached via: log in at /system-login -> /home -> /v2/home -> left nav
"Service Providers" > "Suppliers" > "Add Supplier".

## Acceptance Criteria

- Given the Suppliers index, when a user clicks "Add Supplier" and submits the form with Company, Street Address, City, State, Country, Contact Name, Phone Number, Email, Lead Time to US (Days), and Balance Timing filled in, then the supplier is created, a "Supplier created successfully." confirmation is shown, and the new supplier appears in the index list with the entered name, location, and contact.
- Given the Add Supplier form, when a user submits it without selecting a Balance Timing, then a validation error ("The balance payment timing field is required.") is shown and no supplier is created.
- Given the Add Supplier form, when a user submits it without a Company name, then a validation error ("The company name field is required.") is shown and no supplier is created.

## Notes

Tag this feature: `service-providers`, `suppliers`, `create`

Covered end-to-end in `tests/test_ServiceProviders_Suppliers_Create.spec.ts`.
As with the Suppliers Index feature, the heuristic (non-LLM) Planner
fallback in `agents/planner/plannerAgent.ts` only understands simple
email/password login flows, so this feature's `TestPlan` and the
page-object code itself were authored directly rather than generated by the
regex heuristic.

Every field and selector in `pages/SuppliersPage.ts`'s create-drawer support
was confirmed against the live app (not guessed), using
@faker-js/faker-generated data (FakeFiller-style) instead of hardcoded
strings. Two non-obvious findings from that process, not visible from the
UI alone:

- "Balance Timing" has no "*" in the UI (unlike Company, Street Address,
  State, Country, Contact Name, Phone Number, Email, and Lead Time to US,
  which all do), but the server rejects a submission without it — this is
  the suite's one negative-path test.
- "City" likewise has no "*" in the UI, but is a NOT NULL database column
  with no validation rule behind it: submitting the form without a City
  does not fail gracefully, it 500s with a raw, unhandled Laravel debug
  page that discloses the SQL query, stack trace, internal DB host/port,
  and request cookies. This looks like both an application bug and a
  security exposure (debug mode enabled) and is **not** covered by an
  automated test here — asserting a crash page as "expected behavior"
  would bake in the bug rather than guard against it, and repeatedly
  capturing that page in screenshots/traces isn't good practice. `city` is
  always supplied by `SuppliersPage.createSupplier`/`submitCreateDrawer`
  callers as a result. See `.agent-memory/project_conventions.md`.

Both findings, plus the KTUI "data-kt-select" combobox mechanics (Country,
Balance Timing) and the duplicate desktop/mobile button/banner markup
pattern, are recorded in `.agent-memory/project_conventions.md`.
