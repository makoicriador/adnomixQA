# Feature: Service Providers - Customs Brokers Edit

As an ADX Manager admin, I want to edit an existing customs broker's
details so that its contact information and location stay accurate over
time.

URL: https://adxmanager.dev/v2/service-providers/customs-brokers/{id}
(the row's own detail page — see Notes for why this section has no
`/edit` URL)
Reached via: log in at /system-login -> /home -> /v2/home -> left nav
"Service Providers" > "Customs Brokers" > a row's company name link >
"Edit" button on the detail page.

## Acceptance Criteria

- Given an existing customs broker, when a user edits its Contact Name, Telephone Number, Email, and Note and saves, then a "Customs broker updated successfully." confirmation is shown and the detail page reflects the new values.
- Given an existing customs broker, when a user edits its Company Name, City, State, and Country and saves, then the detail page shows the new company name and the index list reflects both the new name and the new "{city}, {state}, {country}" location.
- Given an existing customs broker, when a user clears its Company Name and saves, then a validation error ("The company name field is required.") is shown and its existing name is left unchanged.

## Notes

Tag this feature: `service-providers`, `customs-brokers`, `edit`

Covered end-to-end in `tests/test_ServiceProviders_CustomsBrokers_Edit.spec.ts`.
As with the Suppliers features, the heuristic (non-LLM) Planner fallback in
`agents/planner/plannerAgent.ts` only understands simple email/password
login flows, so this feature's `TestPlan` and the page-object code itself
were authored directly rather than generated by the regex heuristic.

The suite creates its own throwaway fixture (via
`CustomsBrokersPage.createCustomsBroker`) rather than editing a real,
pre-existing customs broker, so it never mutates shared data.

**This section's Edit flow is genuinely different from Suppliers/Freight
Forwarders — confirmed live, not assumed:**

- A row's kebab (⋮) menu on the index has **no "Edit" action at all**, only
  "Deactivate". Editing is only reachable from the broker's own detail page
  via its "Edit" button (`#edit-button`).
- That "Edit" button is a client-side drawer toggle
  (`data-kt-drawer-toggle="#edit-customs-broker-drawer"`), not a real link
  to a separate `/edit` URL — clicking it does not navigate anywhere, and
  saving keeps the browser on the same detail URL throughout.

`CustomsBrokersPage.openEditFor` reflects this: it clicks into the row's
detail page first, then clicks the in-page Edit button, rather than
reusing the kebab-menu pattern from `SuppliersPage`/`FreightForwardersPage`.
