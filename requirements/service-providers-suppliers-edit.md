# Feature: Service Providers - Suppliers Edit

As an ADX Manager admin, I want to edit an existing supplier's details so
that its contact information and location stay accurate over time.

URL: https://adxmanager.dev/v2/service-providers/suppliers/{id}/edit
(opened from a supplier row's kebab menu on the index, or from its detail
page; on success it redirects to https://adxmanager.dev/v2/service-providers/suppliers/{id})
Reached via: log in at /system-login -> /home -> /v2/home -> left nav
"Service Providers" > "Suppliers" > a row's ⋮ menu > "Edit".

## Acceptance Criteria

- Given an existing supplier, when a user edits its Contact Name, Phone Number, Email, and Business License Number and saves, then a "Supplier details updated successfully." confirmation is shown and the supplier's detail page reflects the new values.
- Given an existing supplier, when a user edits its Company name, City, State, and Country and saves, then the detail page shows the new company name and the Suppliers index list reflects both the new name and the new "{state}, {country}" location.
- Given an existing supplier, when a user clears its Company name and saves, then a validation error ("The company name field is required.") is shown and the supplier's existing name is left unchanged.

## Notes

Tag this feature: `service-providers`, `suppliers`, `edit`

Covered end-to-end in `tests/test_ServiceProviders_Suppliers_Edit.spec.ts`.
As with the Suppliers Index and Create features, the heuristic (non-LLM)
Planner fallback in `agents/planner/plannerAgent.ts` only understands
simple email/password login flows, so this feature's `TestPlan` and the
page-object code itself were authored directly rather than generated by the
regex heuristic.

The suite creates its own throwaway supplier as a fixture (via
`SuppliersPage.createSupplier`) rather than editing one of the real,
pre-existing suppliers the Index suite reads, so it never mutates shared
seed data. Non-obvious findings from editing against the live app (not
guessed):

- The Location column shown on the Suppliers index is "{state}, {country}",
  **not** "{city}, {country}" — city does not appear there at all. The
  Index suite's own location-search test happens to still pass because
  several of the pre-existing Chinese suppliers have their city name
  entered into the State field, but this suite's fixture data makes the
  state/country distinction unambiguous.
- The row's "Edit" action link is matched by a substring role/text query
  (its icon glyph makes an exact match fail — see
  `.agent-memory/project_conventions.md`), which will also match a
  supplier's own name link if that name happens to contain the word
  "Edit" — `SuppliersPage.openEditFor` scopes by the menu-link class to
  avoid this, and the fixture name itself avoids the word entirely.
- A successful save's confirmation banner (like the Create drawer's) is
  rendered twice in the DOM — the same duplicate desktop/mobile markup
  pattern documented for the "Create"/"Save Changes" submit buttons.
