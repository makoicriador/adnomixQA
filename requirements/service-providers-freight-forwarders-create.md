# Feature: Service Providers - Freight Forwarders Create

As an ADX Manager admin, I want to add a new freight forwarder from the
Freight Forwarders index so that it becomes available for shipping without
leaving the page.

URL: https://adxmanager.dev/v2/service-providers/freight-forwarders
("Add Freight Forwarder" button opens the create drawer)
Reached via: log in at /system-login -> /home -> /v2/home -> left nav
"Service Providers" > "Freight Forwarders" > "Add Freight Forwarder".

## Acceptance Criteria

- Given the Freight Forwarders index, when a user clicks "Add Freight Forwarder" and submits the form with Company Name, Street Address, City, State, Country, ZIP Code, Contact Name, Telephone Number, and Email filled in, then the freight forwarder is created, a "Freight forwarder created successfully." confirmation is shown, and it appears in the index list with the entered name, location, and contact.
- Given the Add Freight Forwarder form, when a user submits it without a Company Name, then a validation error ("The company name field is required.") is shown and nothing is created.
- Given the Add Freight Forwarder form, when a user submits it without a City, then a validation error ("The city field is required.") is shown and nothing is created.

## Notes

Tag this feature: `service-providers`, `freight-forwarders`, `create`

Covered end-to-end in `tests/test_ServiceProviders_FreightForwarders_Create.spec.ts`.
As with the Suppliers features, the heuristic (non-LLM) Planner fallback in
`agents/planner/plannerAgent.ts` only understands simple email/password
login flows, so this feature's `TestPlan` and the page-object code itself
were authored directly rather than generated by the regex heuristic.

Every field and selector in `pages/FreightForwardersPage.ts` was confirmed
against the live app (not assumed to match Suppliers, even though the UI
looks similar). Non-obvious findings from that process:

- Unlike Suppliers, **every** field marked "*" in the UI (including City)
  is genuinely required server-side and fails gracefully — no hidden
  required field (Suppliers' Balance Timing) and no unhandled-500 field
  (Suppliers' City). Confirmed live before writing the negative tests.
- On a successful create, this section redirects straight to the new
  record's own detail page — unlike Suppliers/Customs Brokers, which stay
  on the index. The happy-path test navigates back to the index explicitly
  before asserting on the list row.
- The index's Location column here is "{city}, {country}" — a different
  format from Suppliers' "{state}, {country}".
- The "Create" submit button renders only once here (no desktop/mobile
  duplicate, unlike Suppliers' two identical "Create" buttons) — `.first()`
  is still used defensively regardless.
